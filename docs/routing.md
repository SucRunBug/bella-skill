# 主路由与维护

## 一个入口，四个分类

`bella-skill` 是跨技能选择入口。`english`、`research`、`media`、`game-3d` 是分类文件夹，不是多一层必经问答或另一个路由技能。专项技能可以独立使用。

路由参考 dbskill 的三个做法：维护明确候选目录、按接手与交付匹配任务、保留上下文后动态调整。这里只实现本合集所需的部分，没有引入商业诊断、编号提示词、自动更新和其他无关流程。

## 候选真源与安装布局

候选记录在 `skills/bella-skill/references/catalog.json`。每项包含稳定名称、分类、仓库相对路径、旧名称、接手与交付边界、依赖、源仓库和固定提交。上游快照记录导入提交；本仓库新编成员记录实现基线，并在其来源文件注明第三方版本。

`scripts/list_skills.py` 不做关键词自动决策；它只发现真实可用的文件，读取实际安装版本的名称与描述。Agent 结合用户意图判断，随后完整读取选中技能。

查找范围固定为主入口相邻的两种布局：

1. 仓库内：`<skills>/<category>/<name>/SKILL.md`。
2. 平铺安装：`<skills>/<name>/SKILL.md`。

主入口先解析真实位置，因此安装器为宿主创建软链接时仍可工作。缺失、frontmatter 名称不符或两处定义冲突都被明确报告。脚本不会扫描个人目录、读凭据、联网更新或自动安装。

## 阶段与近邻边界

- “这是英语视频，帮我拆解”按拆解交付选视频读取；“用这段材料练口语”按学习交付选口语陪练。
- “科研汇报改成英文”仍按科研写作任务处理，除非用户要做口头演练。
- “做拼贴 B-roll”默认交静帧与视频制作包；要导出实际动画时再检查明确请求和生成能力。
- “已有音乐和歌词，制作动画 MV”进入 `bella-music-mv`：从歌词与节奏安排分镜，编写可编辑的二维角色和场景动画，逐帧渲染并导出成片。它以已有音乐为输入；歌词字幕、口播包装或拼贴静帧本身不等于完成 MV。
- “用产品官网、截图或功能资料做宣传/发布片”进入 `bella-product-promo`，先围绕真实卖点设计产品叙事，再按所需风格与技术制作。已指定技术或只要分镜时沿用；配乐本身不是把产品宣传任务转成音乐 MV 的理由。
- “已有粗剪，加字幕”进入口播包装，不重新选题或写稿。
- “只改这句话”直接定向修改，不重走完整创作流程。
- “做完整游戏”可以承接其中 3D 资产部分，但需说明引擎、玩法与程序等其他工作，不能把一个模型冒充完整游戏。

这些是边界说明，不是固定任务链。多个步骤只在当前请求确实需要时衔接，任何用户已提供的中间产物都可以成为起点。

## 新增或调整成员

1. 将完整技能放入对应分类，目录名与 frontmatter `name` 一致。
2. 更新 `catalog.json` 的名称、路径、接手与排除边界和来源提交。
3. 更新主入口的导航表、根 README 和 `SOURCES.md`。
4. 运行集合检查、目录发现测试和相关成员的离线测试。
5. 用 `skills add ... --list` 检查发现；若改变安装结构，在隔离目录验证完整安装和资源一致性。

不要把个人资料或新的使用记录混入公开包。已有子目录许可证继续保留；来源更新应记录提交，避免把上游更新与整合修改混为一体。
