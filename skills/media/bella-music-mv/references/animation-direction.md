# 动画导演规则

本文件把手绘二维短片原则用于整首 MV。目标是手工感、鲜活表演和完整叙事，同时让观众跟得上。用户指定其他媒介或表现方法时按其要求调整；歌词字幕由统一 overlay 负责，不受场景“少字”的限制。

## 1. 先照顾观众的理解节奏

编码者知道下一秒会发生什么，观众只看一次。每镜先写依次发生的“理解点”（reads）：观众发现目标、辨认含义、理解因果、看见反应，都需要时间。小、远、快、暗或隐蔽的事件需要更多时间。

- 一个时刻只让一个关键理解点占主导。先看到原因，再看到角色反应；不能同时闪现目标、扭头、起跑和切到新地点。
- 动作可以很快，意义要停留。用预备动作告诉观众看哪里，动作后给一个仍有呼吸、眨眼或轻摆的停留，不把“停留”做成卡死。
- 引导眼睛：角色先看目标、灯光或物件先动、镜头先移动到相关位置，再让重要事件发生。
- 不用统一的缓慢或匀速解决问题。快速穿过无关部分，把时间留给发现、选择、结果与反应。
- 先按读点决定镜头复杂度。歌曲时长固定，放不下就删去竞争信息、把动作跨歌词延续，不能把所有事件压在同一个短镜头里。
- 结尾的最终读点也需要成立：回报发生后，允许观众理解和感受，再做退出转场。

可以把一个动作段拆为“看见 → 判断 → 预备 → 行动 → 结果 → 反应”。这不是每镜都要六项，而是防止少了因果。检验时每 0.1–0.15 秒顺序看图，数每个理解点占的帧；单张漂亮静帧不能证明时间安排成立。

## 2. 一个世界，一条线索

- 每镜都有事件：尝试、失败、发现、改变、追赶、变形或得到结果。主角站着微笑加漂浮装饰，不算叙事事件。
- 一镜一项焦点，用大而清晰的剪影，让主动作一眼可读。小动作和背景运动只服务主事件。
- 采用可穿行的场景、可追踪的主角和连续道具，不把每句歌词做成独立卡片。空间可以换，但动作、方向、色彩或形状要带观众过去。
- 全曲使用小调色盘，章节按情绪变化形成色彩弧线；主角与背景始终有足够反差。结尾呼应开场的地点、姿势或母题，并体现变化。
- 副歌回到熟悉空间或动作，再逐次升级编舞、规模、角色关系和环境。重复带来辨识，递进带来剧情。
- 提前设置物件或冲突，并在同镜或后文回报；不要在末尾无来由地加入新道具来结束故事。
- 中景可用约 `u=20–28`，近景约 `40–70`；广景中的小角色不能占满整曲。在副歌的舞蹈主镜头里，主角可接近画面高度的 40%，按目标画幅和字幕安全区调整。

## 3. 把歌词演出来，控制文字

歌词字幕负责用户的原词；动画负责比喻、欲望、情绪、行动和后果。不要额外画与当前歌词同义的标牌、解释字幕或装满字的屏幕，不要用一句“我很伤心”代替低头、迟疑和错失动作。

场景确实需要名字、地名或文字笑点时，少量、一两词、融入画面。反应符号优先使用画出来的汗、心、灯泡、疑问或惊叹标记。显式标题、品牌或其他用户需求按要求执行，不机械套用“禁字”。

歌词 overlay 的字体、行宽、断行与位置全曲统一。让面部、抓握和关键道具远离实际字幕带；换为竖版或方版后重新看画面，不套用横版固定 y 值。高动作镜头可以减少字幕周围装饰，保证文字与事件各自可读。

## 4. 动作像有重量的卡通

| 原则 | 在代码里怎样落实 |
|---|---|
| 预备动作 | 跳前蹲、投前后摆、惊讶前眯眼，让观众预期主动作；`jump()`、`take()`、`emotions()` 已提供部分结构 |
| 挤压拉伸 | 落地挤压、快速运动拉长，配合体积感和接触点，避免身体无故变尺寸 |
| 缓入缓出 | 将进度交给 `ease`、`easeIn`、`easeOut`、`backOut` 等；不用全程线性位移 |
| 重量 | 重物起停慢、余弹少，轻物迅速、可回弹与飘落；音符、石块不共用一条轨迹曲线 |
| 弧线 | 抛物、手臂和跳跃使用 `arcPt()` 或合理曲线，不走僵硬直线 |
| 重叠与余势 | 眼睛先动、身体跟随、手臂帽子最后停，错开各部位时间；可用 `spring()`、`ring()` |
| 避免镜像 | 两臂作用不同，眼神有方向，多人节相与种子错开；整齐编舞是选择，不是复制参数的意外 |
| 夸张 | 推大姿态、倾斜与反应幅度，再从静帧判断是否过头；谨慎到看不见的动作不能讲故事 |
| 强关键姿态 | 先画能单独说明事件的姿态和剪影，再加中间运动 |
| 展示思考 | 注意、判断、选择再行动，眼睛先于身体；反应也是表演的一部分 |
| 次级动作 | 帽子、草、呼吸和表情记号增加生命感，但不盖过主动作 |

节拍用 `PROJECT.bpm`、`PROJECT.offset` 与 `pulse()` 等统一驱动。命中、落地、情绪爆点和大切换落在适合的音乐拍点上，慢歌和情绪镜头也可以跨拍保持；不让每个物件同时按拍弹跳。

脸部变化通过 `emotions()` 的预备、眯眼、反应与恢复完成，避免突然换眼睛和嘴。`feel()` 将情绪绑定为脸、颜色和身体运动；叠加 `jump()`、`turn()` 等姿势时，同字段的 `dy`、`sq` 要显式相加，避免对象展开顺序把某一动作吞掉。

底座的转身是五个手绘关键视角 front、q、side、qback、back 的切换，`turn()` 配合 smear；不是把一个三维盒子投影旋转。默认保持二维，远近来自遮挡、尺度、颜色与分层。走路视角和地面斜率一致，手持道具落在 arm-tip hook，另画的大道具根据同一姿势计算位置并检查接触。

## 5. 转场属于故事

默认在开场、镜间和收尾安排转场。刷痕擦拭、iris/形状遮罩、甩镜与 smear、形状匹配、动作中切镜、跨镜持续运动、从纸面或暗部淡入都可用。单纯硬切只在动作承接或有意的冲击切换时使用。

让转场有动机：物体靠近填满画面后揭示新场景、持续下落带到下一地点、同一方向的追逐跨切、上一镜图形成为下一镜目标。这些是方法，不复制任何已有 MV 的具体角色与镜头。

`brushWipe()` 只是绘画函数，时间线不会自动替所有镜头加转场。总导演和章节作者必须约定边界与颜色，前镜画遮盖的前半段，后镜从完全覆盖时画揭示的后半段。屏幕特效通常放在 `camEnd()` 后；需要覆盖文字时先 `flushLetters()`，注意歌词 overlay 的实际合成次序。

镜内变化也要连接：角色转向走关键视图，表情经过 `emotions()`，道具沿路径进入或离开。转场不能隐藏事件尚未被理解的事实；检查每个接缝前后及相邻音拍。

## 6. 保持笔刷媒介一致

默认所有实体通过 `paint()`、`inkLine()` 绘制：人物和关键道具用平涂 `wash` 加墨线，背景用软水彩 `fill`，少量 hatch 提供干笔纹理。避免同画面混入普通数字形状、光滑渐变或大量噪声，使手绘角色像贴在另一种媒介上。

- 一个形体尽量一个完整外轮廓。尾巴、藤蔓和拖尾用 `ribbon()` 等连续形状，不用一串圆拼成贴纸。
- 水彩按颜料混色，蓝底叠黄会变绿。实体需稳定颜色用满不透明 `wash`；发光用加光 `glow()`，按前后关系绘制，别用反复叠淡黄色把光画脏。
- 默认柔和而清楚：墨色用 `PAL.ink`，亮色用 `PAL.cream` / `PAL.paper`，少用纯黑纯白。章间变化在同一色彩系统内发展。
- 手绘线条以 `BOIL=12` 的频率变化，稳定对象的位置用 `hash(i)`；抖动用 `jit()` 和有固定 key 的 `boilSeed()`。
- **每个独立元素独立播种。** 否则前面运动物体消耗不同数量的随机数，会使后面的静止物体每帧乱跳。每个背景层、道具、特效各有稳定 key；角色进出场时为 `clawd()` 指定稳定 `boilKey`，不要只依赖调用序号。

对笔刷异常使用具体修复：

- 放大镜头下，大世界坐标的线可能坍成点。优先用底座围绕形状中心绘制的封装；特别大的轮廓拆成不超过画布尺度的线段。
- 描边是世界单位，会随镜头放大；小对象近景变成墨团时按 zoom 缩小 `sw`。
- 点列表出现 NaN 可能抛出看似无关的 `OffscreenCanvas` 尺寸错误；先检查退化几何、零分母和越界 `acos`，不是盲目重启 Chrome。
- `push/pop`、`camBegin/camEnd` 成对，镜头只用一层。全屏特效在屏幕坐标绘制，确保每镜开始/结束的变换不泄漏。

## 7. 时间纯函数与成本

同一 `t` 必须得到同一设计帧，所有移动、弹簧、弧线和随机布局从时间及稳定种子计算。不能累计位置、存上一帧速度、依赖播放次数或使用 `Math.random()`；离线并行会乱序取帧，这些状态会使出片不一致。

画面有手绘变化不代表可以随机闪烁。检查逐帧条时，同一 boil 时段中没运动的部件应保持一致；底座默认 24fps 和 12Hz boil 通常相邻两帧共用一次笔触，换 fps 后依据时间判断，不机械数两帧。

成本主要来自笔触与水彩 `fill` 的数量。优先少而大的形体、清晰层次，减少数千个小形状；弱 GPU 可用更多平涂与墨线保留画风。抽样测量每帧耗时，再估整曲成本，不能为追求复杂而把主事件淹没，也不能用省时为理由只完成几秒。

## 8. 使用上游参考的方式

[完整上游动画指南](upstream-animation-guide.md) 保留了 API 与例子的细节。查代码时重点搜索：

- `Painting`：点列表、填充、笔刷、hatch、ribbon、glow 及 p5.brush 陷阱。
- `Time and motion`：插值、拍点、跳跃、弹簧、弧线、镜头和全屏效果。
- `Clawd`：视角、31 种情绪、姿态、脸部、道具 hook 和舞蹈。
- `Frames are pure functions of time`：独立帧、稳定随机流。
- `Worked example`：学习把因果、结果和反应分开安排的推理，不照抄其星星故事、构图、时间数字或结尾。

沿用的是有许可的引擎与动画方法。新 MV 的主角、场景、母题和镜头从用户音乐重新设计；PDoomVideo 的歌曲、原分镜和未明确许可代码不进入技能包或用户成片。
