# MV 制作工作流

本文件负责整曲编排、输入时间与工程协作。具体笔触、表演和观众理解节奏见 [动画导演规则](animation-direction.md)；本包扩展的参数与运行约定见 [MV 引擎接口](engine-api.md)，继承的绘画和角色 API 见 [上游指南](upstream-animation-guide.md)。

## 1. 输入与工作目录

从用户附件和对话中找到原曲与完整歌词。纯文本歌词也足以开始；不要把风格、画幅、BPM、人物或字幕偏好当作必须回答的问题。缺少音频或歌词时补问缺项，其他设置依据已有要求或默认值决定。

建立独立项目目录，保留原始材料；已有项目继续在对应工程中修改，不重新初始化覆盖。输入发生变动时核对 `project.json` 的设置和输入指纹，不能沿用与新歌曲不符的旧分析、歌词时间或帧缓存。

```bash
python3 scripts/mv.py doctor
python3 scripts/mv.py init --audio "/absolute/song.mp3" --lyrics "/absolute/lyrics.lrc" --project "/absolute/my-mv"
python3 scripts/mv.py install --project "/absolute/my-mv"
python3 scripts/mv.py analyze --project "/absolute/my-mv"
```

根据指定需求给 `init` 增加 `--aspect portrait`、`--captions line`、`--bpm 100`、`--offset 0.2`、`--fps 24` 等。横版、竖版和方版必须按目标画布重新安排人物与字幕，不能只把横版中心切掉。`install` 执行项目锁定依赖安装，已有依赖时跳过。调用脚本后检查实际生成文件和帮助信息；失败时不要凭命令名称假定生成了结果。

初始化后的主要文件：

| 路径 | 责任与用途 |
|---|---|
| `project.json` | 项目设置、输入位置与指纹；变更时同步维护 |
| `analysis.json` | 本地音频分析结果；节拍与结构候选需判断 |
| `lyrics.json` | 规范歌词与时间数据，最终时间以此为依据 |
| `src/config.js` | 时长、BPM、offset、画幅等运行配置 |
| `src/lyrics.js` | 从 `lyrics.json` 同步的浏览器歌词数据 |
| `src/mv.js` | 底座统一歌词叠加与可检查元数据 |
| `STORYBOARD.md` | agent 编写的全曲叙事、章节和镜头计划 |
| `src/scenes/video.js` | 总导演入口；初始化时未实现 |
| `src/scenes/cXX_*.js` | 已实现章节，每文件一位作者 |
| `studio.html` | 引擎、共享资产、章节脚本的实际加载次序 |

## 2. 音乐、歌词和时间依据

先读取原曲时长与声流，用本地波形/RMS 分析辅助识别能量起伏、可能的拍点和段落变化。算法的节拍候选不是歌曲结构真值：半拍/双倍速、弱起、自由前奏、变速都可能误导。结合用户时间资料、可用音频工具和实际听感，把主歌、副歌、桥段、前奏、间奏、尾奏写入计划；不要只按等时长机械切段。

歌词可为 plain、LRC、SRT、VTT 或 JSON。JSON 规范为对象数组，每项至少包含：

```json
[
  {
    "start": 12.2,
    "end": 15.8,
    "text": "用户提供的原句",
    "timing": "aligned",
    "source": "真实词级对齐及核对记录的位置（本项仅为格式示意）",
    "wordTiming": "exact",
    "words": [
      { "start": 12.2, "end": 13.1, "text": "用户" },
      { "start": 13.1, "end": 15.8, "text": "提供的原句" }
    ]
  }
]
```

`words` 可省略；有时才使用真实词时间，词必须落在线时间内并保持顺序，忽略空白后拼起来须等于完整原句。`timing` 与 `source` 记录实际依据，只有完成真实词级对齐与核对后才设 `wordTiming: "exact"`。示意数据只解释结构，不是对齐模型，也不进入用户成片。

时间来源按实际过程记录于项目数据或检查记录：

- `provided`：用户提供了这些时间戳；仍需检查格式、顺序、范围和明显偏移。
- `aligned`：有实际执行的对齐过程与输出，记录工具/方法及修正，不因格式像 LRC 就这样标注。它可以仅为句级对齐；没有经过核对的词级时间时，不添加 `wordTiming: "exact"`。
- `approximate`：按长度、段落或人工粗排估计。纯文本默认属于此类；没有逐词对齐就不能声称精准逐字同步。

只在环境已有可用工具且符合用户范围时以 ASR/强制对齐辅助，不为启动任务自动下载大模型，不上传原曲到第三方。无对齐能力仍继续创作，诚实保留 `approximate`，抽查开头、中段、结尾及每章边界。修正长期漂移不能只统一平移整首歌词。估算的 karaoke 扫描也需标明属于视觉进度估计。

无歌词的前奏、间奏和尾奏留出无字幕时段。保持原词、语言与顺序；重排换行不能重写歌词。长句分行，重复句保留其每次出现。中文字幕选择本地支持中文的字体，并抽看实际字形，不能让缺字方框进入成片。

修改 `lyrics.json` 后运行 `python3 scripts/mv.py sync --project "/absolute/my-mv"`，不要只改生成的 `src/lyrics.js`；检查会拒绝两者不一致。渲染器只在 `wordTiming` 为 `exact`（或兼容的 `timing: "exact"`）且有有效 `words` 时按词高亮，其他情况使用整行进度。不要为了开启效果把估算数据改标为 exact。

## 3. 总导演先写全曲方案

分镜写盘并简短告知用户后继续实施，不默认等待审批。方案至少包含：

```text
一句话故事：主角想要什么，遇到什么，最终发生什么变化。
世界：场景体系、小调色盘、光线与全曲色彩变化。
角色：轮廓、尺度、配饰、关键视角、表情与动作约定。
母题：反复出现的动作/物件/图形，如何升级并在结尾回报。
情绪弧线：沿全曲发展的情绪关键点。
章节：名称、起止秒、对应歌词/器乐段、调色盘、进入/离开状态。
镜头：起止秒、画面事件、角色反应、镜头运动、拍点、进出转场。
reads：观众先理解什么、再理解什么，各自起止秒，眼睛如何被引导。
字幕：当前画幅的安全区、长句与高动作段的布局。
```

用场景和动作演出歌词意义。每章可拥有自己的地点，但必须属于同一世界；主角方向、物件、动作或色彩承接下一章。副歌回到辨识度高的视觉空间，每次改变规模、编舞、环境或情绪。间奏承担追逐、转换、反应或母题演变，不能退化成空转背景。结尾呼应开头，并给最后的理解点留时间。

歌词在快速演唱时可以快速变化，**视觉事件不必每句同时换一个世界**。读点放不下时简化画面信息、跨句延续动作；不要让角色反应、关键道具和切镜一起抢注意力。MV 总时长来自歌曲，不能靠任意拉长音乐为过载分镜找时间。

在章节开始/结束记录接力状态：角色位置和朝向、手中物件、情绪、镜头方向、背景与转场颜色，尤其写清跨章转场的遮盖时刻和揭示时刻。

## 4. 共享接口后按章节实施

总导演在并行前完成公共设计和可调用接口。章节任务书提供：准确时间范围、歌词、镜头/reads、角色与道具 API、调色盘、安全区、首尾接力状态、允许编辑的唯一文件及检查输出位置。

共享的 `core.js`、`clawd.js`、`timeline.js`、`lyrics.js`、`config.js`、`studio.html`、`render.mjs` 由总导演统一修改。章节作者只改自己的 IIFE 文件；缺少非复用辅助函数就在私有作用域实现，确有共享 bug 或新增需求时报告总导演。共用客串角色与道具先约定名称和接口，避免不同章节各画出不同版本。

底座支持 `chapter(name, start, end, shots)`；镜头为 `fn(t, lt, dur)`，分别表示整曲时间、镜头局部时间与镜头长度。章节时间不重叠、不留未实现空洞，实际 `shots` 起点与章节范围匹配。主时间线选择章节注册或全局 `shots()` 之一，不能混用。总导演维护脚本加载顺序和 `video.js` 装配说明，禁止把“已规划”当作“已注册并实现”。

先画关键姿态并抽静帧，再写其间运动，最后做首尾衔接。帧必须由 `t` 独立计算，每镜重画完整背景；所有并行作者遵循相同的随机播种与镜头恢复规则。没有子 agent 能力时，总导演按章节串行完成，不因此停在分镜阶段。

## 5. 把检查做成实际反馈

使用包装器检查并生成视觉材料：

```bash
python3 scripts/mv.py check --project "/absolute/my-mv" --draft
python3 scripts/mv.py render --project "/absolute/my-mv" --draft --sheet=0.1,1.2,2.4 --cols=3 --w=640 --out=out/check/opening.jpg
python3 scripts/mv.py render --project "/absolute/my-mv" --draft --strip=2.0:2.5 --cols=6 --w=320 --out=out/check/turn.jpg
python3 scripts/mv.py render --project "/absolute/my-mv" --draft --sheet=2.1,2.2 --crop=760,300,400,400 --w=600 --out=out/check/face.jpg
python3 scripts/mv.py render --project "/absolute/my-mv" --draft --strip=2.0:2.5 --crop-at=960,700,500,400 --out=out/check/contact.jpg
python3 scripts/mv.py render --project "/absolute/my-mv" --draft --clip --range=0:8 --out=out/check/opening.mp4
```

示例中的时间与坐标必须替换为当前已实现镜头的真实值。工作中的预览用显式 `--draft`；未完成范围不计为成片覆盖。`--crop` 是固定屏幕区域；`--crop-at` 跟随世界点经镜头变换的位置，不会自动跟踪角色；裁剪前仍完整渲染画面，不是节省绘制成本的局部渲染。

检查预算按风险放在实际镜头上：

- 每镜一组首、中、尾及关键姿态 sheet，核对事件能否从图上看懂、人物大小、色彩与字幕安全区。
- 每个关键转身、跳跃、抛接、情绪切换及转场一段逐帧条，检查预备、主动作、余势、接触和突然跳变。
- 承担叙事的脸与手、脚、发光处做 full-resolution crop，检查眼神、抓握、落地、阴影与光的层次。
- 复杂读点每 0.1–0.15 秒抽一张，顺序读图并数它实际占了多少帧；关键因果依次发生，不能只看好看的单帧。
- 每章带音频短片检查节拍、字幕偏移和读点速度；章间两侧各至少检查约 0.5 秒；整合后再检查跨章节连续性。

打开生成结果，写下实际发现与修正到项目内的检查记录。发现遮挡、机械运动、太小、泥色光、飞离手掌或突兀断场就修复并重看。渲染日志里每帧耗时可用于预算，不将某台机器的速度承诺为通用速度。

先跑 `doctor` 定位 Node、Chrome、ffmpeg。跨平台 GPU 配置与 `--soft-gl` 可用时先抽一帧验证实际 renderer；无法建立 WebGL context 时不要反复重跑全片。软件渲染慢时减少水彩 `fill` 数、缩减背景复杂度，保留主事件、表演和完整覆盖。

## 6. 正式渲染与成片核验

全部实际镜头实现后，更新 `video.js` 的 `MV_VIDEO` 完成元数据，将 `src/config.js` 内 `PROJECT.status` 改为 `authored`。`config.js` 保持 `const PROJECT = JSON对象;` 格式：属性名与字符串用双引号，不放注释、尾随逗号或 JS 表达式在对象内部，避免包装器无法读取。仅改状态不能替代实现；`check` 还需确认实际加载脚本的镜头已覆盖全曲且没有占位，之后正式渲染。草稿可以帮助迭代，但不能跳过源码覆盖和最终画幅的检查。

```bash
python3 scripts/mv.py render --project "/absolute/my-mv" --draft
python3 scripts/mv.py render --project "/absolute/my-mv"
python3 scripts/mv.py verify --project "/absolute/my-mv" --video out/video.mp4
```

修改源代码、fps、画幅、歌词或输入歌曲后，按包装器实际的缓存管理行为重渲染受影响输出；绕过包装器使用上游 `--frames` 时，不依赖“文件存在”判断新旧版本，清理对应旧帧，防止拼入旧画面。两阶段渲染和编码必须使用同一 fps；编码时确认真实音频被挂载，不能只检查视频能播放。

`verify` 用于核验文件和声画参数。再用实际图像/预览抽查开场、每章、跨章、结尾及最后一帧，确认全曲没有空白、demo、未完成画面、缺字和突然截断；前后声画时长应合理相符。以实际退出状态、输出文件及 `verify` 结果为准，不用一条完成日志代替核验。

最终给用户完整成片链接、工程目录与分镜链接，并说明画幅/时长/字幕模式和时间依据。仍为估算时写明，未实现片段或依赖阻断时准确写出剩余项，不能改名成片或降格交付一个示例。后续只改局部时保留已通过检查的其他章节，并核对相关共享改动是否影响全片。
