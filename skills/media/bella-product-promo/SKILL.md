# Bella 产品宣传片

把产品的真实价值变成能看懂、能记住的影像。根据用户目标选择表现方式，由 agent 完成调研、文案、分镜、动画、声音、渲染和检查；用户无需学习动画库或运行命令。

## 从用户已有材料开始

先恢复对话里的产品、资料、喜欢的参考、发布位置、输出范围和已有工程。用户只要求提示词、方案、静帧或局部修改时，就交付该范围；已要求成片且材料足够时持续制作，不能停在计划或脚手架。

首次只补问会改变制作的缺口，一次尽量不超过三项：

1. **宣传什么？** 产品网址或一段介绍；已有截图、Logo、代码、演示视频时直接使用。
2. **给谁看，最想让他记住什么？** 目标用户与一个主卖点；可从可靠产品资料提出建议，不虚构结论。
3. **发在哪里？** 发布平台、时长或横竖版；未决定可以自动推荐。

用户只知道“想做宣传片”时，先让他用一句话说清产品，给可直接填空的示例；不要同时索要完整品牌手册、专业参数和素材清单。已有信息不重复问，缺非必要素材时先做不依赖它的调研与分镜。用户说“你来定”时采用合理默认值并继续，不强迫填写问卷。

默认成片为约 20 秒、1920×1080、30 fps；明确用于竖屏信息流时采用 1080×1920。精细 UI 或用户要求顺滑效果时可推荐 60 fps，并考虑渲染成本。尊重指定时长、规格、语言、字幕、声音和平台约束。输出中文字时检查字体与断行。

面向新手的自然语言开场、输入示例、选风格与提出修改的方法见 [用户引导](references/user-guide.md)。不要把内部命令和完整技术清单一次性推给用户。

## 风格先讲观感，技术按任务推荐

先看 [风格速选](references/styles.md) 的概览，再按产品推荐最相关的两到三种，说明观感差异与取舍。用户可选择、混合或全自动；已有参考片就沿用该方向，不再次要求选菜单。

| 风格 ID | 用户看到的效果 | 优先场景 |
|---|---|---|
| `spotify-premium` | 深色舞台、品牌色、精细 UI、封面与播放器贯穿转场 | 品牌质感与软件体验 |
| `minimal-ui` | 浅色留白、同一形状连续变成真实产品控件 | 用一个操作流程解释产品 |
| `tech-launch` | 深色科技感、代码、数据流和结构化功能叙事 | AI、开发工具、技术产品 |
| `real-ui` | 真实截图拆成组件与图标，配合音乐逐一运动 | 已有成熟界面的 SaaS/App |
| `social-launch` | 开头钩子、卖点证明、快速节拍与清晰品牌落点 | 社媒上新与活动发布 |
| `apple-continuous` | 液态玻璃、照片、设备与页面一镜到底地变形 | 设计感强的产品与品牌 |
| `footage-hybrid` | 真实视频、界面、案例墙与数据结果组合 | 有案例、用户内容或实拍素材的产品 |
| `outcome-story` | 从交给产品一项任务，到得到有价值的结果 | Agent、自动化、效率服务 |
| `shape-morph` | 一个输入框、按钮或形状贯穿完成整个故事 | 用少量素材做精炼的产品概念片 |

这些是起点，不是审美上限。可按品牌改成明亮、温暖、手绘、复古、极简或更写实的视觉语言；明确哪些是已有完整参考、哪些是这次重新设计，不能宣称每个变体都有现成模板。风格与技术分开选择：同一风格可用不同引擎实现，不因偏好某个库而改变用户要的效果。

| 技术 ID | 何时采用 | 用户需要理解的取舍 |
|---|---|---|
| `native-html` | HTML / Canvas / SVG / CSS，排版、图形、界面和轻量 2D | 文件少，易改；复杂 3D 不适合硬画 |
| `gsap` | 复杂的控件形变、遮罩、字形和连续时间线 | 便于精细编排；导出仍需可寻帧渲染 |
| `remotion` | React / TypeScript 组件、多尺寸、多版本和数据驱动视频 | 内容组件化强；使用原生帧号与官方导出机制 |
| `threejs` | 真 3D 产品、设备、材质、灯光、镜头和空间轮播 | 空间表现更好；需要控制 GPU 与渲染成本 |
| `blender` | 写实实体产品、复杂材质、机构或高质量离线 3D | 制作和渲染较重；先检查 Blender 与资产 |
| `hybrid` | 真实界面、拍摄片段、动画、配音与音乐混合 | 最依赖真实素材；素材解码、帧率与声音要统一 |

默认由 agent 结合已有工程、素材、效果和可用环境推荐，向用户用一句话解释收益即可。指定技术时保留它；发现具体限制再解释并给替代方案，不静默换引擎。到实施阶段读 [技术路线](references/technology.md) 中所选路线，版本和 API 以项目已安装版本及对应官方文档为准。安装本 skill 不等于已安装所有引擎。

## 读取原文，保留细节，限制加载范围

先读 [提示词索引](references/prompt-library.md) 定位来源，再**完整读取当前风格对应的一份主参考**；确实需要补充声音、转场或素材方法时，再读取一份相关参考。完整原文位于 `references/original-prompts/`，12 份原始 Markdown 按字节保留，含原作者、原帖和观看入口；固定版本、许可和哈希见 [来源记录](references/provenance.md)。机器可读选择表为 [presets.json](references/presets.json)。

- 不把长原文预先缩成几句通用建议，也不一次读入全部原文。具体设计时回到相关原文检查分镜、字体、材质、遮罩、声音、寻帧、导出与验收细节。
- 原文中的品牌、产品事实、数字、样例台词、默认素材、模型名、时长、BPM、帧率和库都是**该例的条件**。为当前产品重写事实和脚本，按当前画幅与时长重排时间线；不能只替换 Logo 后照搬原作卖点。
- `ask me`、`show me before coding` 等原示例流程不自动构成新的审批门槛；已有用户授权和本轮范围优先。用户明确要先审方案时才等待。
- 区分完整指令、需填写输入的模板、简短开放 brief，以及需要真实 UI/照片/音乐的素材依赖；“完整提示词”不代表含全部制作对话、素材或原动画源码。
- 重做版技术标签不证明原作使用同一引擎；原视频展示时长也不一定等于提示词要求。没有实际观看视频时只按提示词分析，不声称已看过成片。

## 从 brief 到成片

实施前读 [制作工作流](references/production-workflow.md) 的通用流程，并只读当前风格的细化部分。

1. **产品事实与素材。** 从用户资料、实际代码或可访问官网提取受众、主卖点、可证明的功能和 CTA，记录依据。列出 Logo、字体、截图、产品图、拍摄、音乐和声音的已有项与缺口。真实界面要求就使用真实界面；重绘示意要说明，不能冒充实测画面。样例里的竞争对手数、ROAS、营收、用户量等不能自动迁移。
2. **一条主线与可执行分镜。** 在用户项目中保存制作 brief，说明风格、技术、规格、素材与待确认事实。用 `STORYBOARD.md` 逐镜写时间、画面、屏幕文字、动作、转场、声音和卖点依据；以“用户问题 → 产品完成关键任务 → 结果/证据 → 品牌与下一步”组织，而非堆功能标题。把方向简短告诉用户后继续实现；没有要求审批就不等待。
3. **先实现共用规则，再做镜头。** 统一字体、调色盘、网格、安全区、组件、镜头语言与 easing；保留真正贯穿的视觉对象。把文案、素材、节拍、时长和尺寸设为配置，方便替换。只对真实需要的章节并行，公共组件和时间轴由一个负责人整合。
4. **声音与动作一起编排。** 依据所选风格决定配乐、合成 UI 音效、旁白或无声；不要给所有风格强加 BGM。音乐有节拍时测量节拍和 drop，用声效的可听峰值对齐动作，不按音频文件起点猜。旁白要给信息留阅读时间，音乐在说话时适当降低，素材需具备相应使用条件。
5. **检查再全量渲染。** 先打开关键静帧和逐拍接触表，检查文字、留白、真实 UI、转场交接和 CTA；再看带声音的短预览，修正节奏、可读性、音画同步和动态缺陷。定格检查不能替代运动检查。复杂形变、液态玻璃、快速缩放和首尾循环按工作流里的专门规则检查。
6. **导出与回看。** 实际渲染 MP4，检查视频与所需音频流、尺寸、帧率、时长、完整覆盖与结尾；打开输出抽看开头、中段、结尾和高风险转场。命令成功不代表画面合格。交付真实成片、完整可编辑工程、分镜、运行/导出方法、素材来源和实际检查记录。

## 随包工具：可用入口与边界

命令中的路径从本技能目录解析；项目路径可在任意目录，含空格时加引号。普通用户无需执行，由 agent 操作。

```bash
python3 scripts/promo.py list
python3 scripts/promo.py doctor
python3 scripts/promo.py init --project "/path/to/promo-project" --product "产品名称" --style minimal-ui --tech native-html --duration 20 --fps 60 --aspect 16:9
```

`init` 创建 brief 与相应路线的制作起点，初始状态为 `unstarted`，**不会自动完成宣传片**。继续研究产品、写分镜并实现全部镜头后，才将 `brief.json` 的 `status` 改为 `authored`，移除未制作占位并检查：

```bash
python3 scripts/promo.py check --project "/path/to/promo-project"
```

内置浏览器起步工程用于 `native-html`，也可作为 `gsap` / `threejs` 的可寻帧输出底座；后两种引擎需要 agent 实际接入。渲染入口、项目内依赖准备、字体/图像就绪、可选运动模糊和音轨合成见 [技术路线](references/technology.md)。`remotion`、`blender`、`hybrid` 依所选项目的真实工具导出，不假称此脚手架已内置全部引擎。

浏览器路线使用 `async window.seek(t)` 和绝对时间计算整帧；等待字体、图片和必要视频帧准备好。正式导出不能依赖实时播放、前一帧、未固定的随机数或未受控 CSS transition。Remotion 使用帧号，Blender 使用明确帧范围与可复现场景状态。

```bash
python3 scripts/promo.py verify "/path/to/promo-project/out/video.mp4" --project "/path/to/promo-project"
```

需要音轨时加 `--expect-audio`。该检查只覆盖实际媒体规格，不能证明品牌、画面、音质或广告事实正确；仍需视觉与听觉检查。依赖缺失时先尝试适用的本地修复；无法继续则保留工程，明确具体阻断与剩余步骤，不用静态网页、黑屏、示例动画或未制作模板冒充成片。

## 修改与交付的范围

用户可用“第 6 秒按钮变慢一点”“改成竖版”“换成明亮风格”“保留画面，换配乐”等自然语言提出修改。先定位共享配置与受影响镜头，保留已确认内容，重新渲染相关预览并交付要求范围内的完整版本；改全局尺寸、字体或节拍时重新核对所有镜头。

制作视频的授权不自动包括投放、发社媒、上传用户素材到外部服务或购买音乐/模型额度。默认在用户项目中完成制作；用户明确要求外部动作时按其具体授权执行。
