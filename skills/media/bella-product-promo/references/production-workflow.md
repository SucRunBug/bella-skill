# 产品宣传片制作与验收

本文件用于从 brief 到成片的实施。按任务规模裁剪，先读通用部分，再只读所选风格或技术相关段落。用户只要提示词、方案或预览时，在对应产物处交付，不扩大范围。用户已要求制作且输入足够时，brief、分镜和关键帧是工作产物与内部检查，不是新增用户审批关卡。

阅读定位：

- 产品与范围：产品事实、brief、素材清单、中文分镜。
- 工程与节奏：可寻帧时间线、转场、音乐与音效。
- 风格细节：Spotify、Sprites／连续形变、TanStack、真实 UI、Supademo、Apple、混合素材、结果故事。
- 实际交付：关键帧与小样、全片导出、验收、定点修改。

原始长提示词完整保存在 [original-prompts/](original-prompts/)，风格到原文的路由在 [styles.md](styles.md)。不要把所有原文一次载入上下文，也不要用本文件代替原文存档。

## 1. 把真实产品转成可拍的 brief

### 先确定事实与本次范围

从用户、官网、实际界面、用户指定的代码／文档或现有素材确认：产品做什么、给谁用、本次主卖点、能直接展示的证据、真实用户流程、品牌、CTA。记录来源和访问日期。无法访问官网时，用已有资料继续；缺核心事实才补问。

把“产品具备的能力”“本片如何演示”“尚待确认的说法”分开。演示数据可以帮助说明操作，但不能被包装成真实客户成果。画面上的数量、百分比、价格、客户名、评价、集成能力和发布状态都要有依据；不具备依据的效果承诺删掉或换成可直接观察的动作与输出。

只研究有助于当前影片的内容，不把一部短片扩大为全套广告战略、十余个人群或整套投放计划。原例让模型随机选 SaaS 时，本次仍以用户指定产品为准。

### 简明 brief 应包含

| 项目 | 要写清的决策 |
|---|---|
| 产品与受众 | 名称、网址／事实来源、目标观众及其先验知识 |
| 唯一主张 | 观众最终应记住的一句话，以及画面如何证明它 |
| 内容边界 | 本次展示的 1–3 个能力；不展示或尚未验证的内容 |
| 平台与规格 | 发布用途、比例、像素、fps、准确时长、手机／投影的可读要求 |
| 风格与技术 | 一个主 style，可选辅助手法；选定 tech 及理由、可用环境 |
| 品牌与视觉 | 色、字体、Logo、主视觉、背景、镜头规律，缺素材时的替代方式 |
| 声音 | 无声／UI 音效／音乐／旁白的组合、语言、音轨来源；不能默认强制 BGM |
| 交付 | 需要的 MP4、预览、字幕、源工程、素材、复现方式；若仅要方案则明确 |
| 假设与缺项 | 可逆的默认值、尚缺资产、会影响准确性或完成度的限制 |

对于用户未指定的低影响参数，结合平台、环境与内容作合理默认并说明。不要照抄原例 18 秒、120 BPM、绿色或 60fps；也不要把“某平台可用”说成已满足其当前上传规范，除非确实核对。

## 2. 建立素材清单与来源记录

素材只为已选镜头服务。先复用用户有权提供的资产，再检查官方媒体包或明确可用的公开素材。网页可浏览不等于其素材已获得用于宣传片的许可；需要确认的权利状态记录为待确认，不冒充已授权。

清单至少覆盖：

| 字段 | 内容 |
|---|---|
| 资产 id／本地路径 | 稳定命名，后续分镜与工程引用同一 id |
| 用途 | 具体镜头、hero、图标、UI、字体、音乐、SFX、旁白、模型等 |
| 来源 | 用户提供／官方地址／原创生成／素材库页面，记录获取日期 |
| 权利依据 | 用户说明、具体许可／授权地址、署名要求、商用范围、待确认项 |
| 技术信息 | 图片尺寸、透明背景；视频时长／fps／分辨率；音频采样率／声道；模型格式 |
| 处理记录 | 裁切、去敏感数据、抠图、分层、重编码、替换或原样使用 |

不要只保存直链而失去素材页与许可来源。授权不足时可用原创辅助图形、用户已授权资产或换镜头；购买、开通付费服务或外部发布不在本地制作的默认范围。

### 不同输入的准备

- **Logo／字体**：优先矢量和可本地加载的字体。图标描边统一；中文字体确认覆盖实际文案，等待字体加载完成后测量布局。文字尽量保留为可编辑文本，不嵌在生成图里。
- **真实 UI**：保留一套原始截图／录屏作参考；制作所需的面板、按钮、卡片、图表拆分为有来源的可编辑组件。去除账号、客户数据和无关浏览器界面。重排可以服务可读性，但不能制造不存在的功能。
- **照片／hero**：确认比例和足够像素，建立统一的裁切锚点。同一张 hero 在缩略图、详情和放大镜头中复用同一资产，不每镜重新生成一个相似物。
- **视频**：先探测时长、fps、可解码性和方向，记录有效片段。导出时使用可确定寻帧的方式；不要依靠网络播放和实时 `<video>` 播放进度。
- **音乐／SFX／旁白**：检查完整文件与使用许可，记录采样率、起点、峰值时刻和裁切。若旁白，先定稿和发音，按真实语音长度调整镜头，不能用脚本文字估时冒充已合成语音。
- **模型**：检查尺度、贴图、相机和所需视角；没有模型时先判断照片与二维是否足够，不自动购买或调用付费建模。

## 3. 写中文分镜与时间／节奏表

每镜回答“观众理解了什么”和“前后如何接上”。即使成片用英文，内部说明仍用中文；屏幕文案与旁白按用户目标语言给出准确文本。完整分镜不是堆形容词。

| 字段 | 填写要求 |
|---|---|
| 镜号、起止时间 | 连续、不重叠、覆盖准确总时长；必要时给输出帧号与节拍号 |
| 目的与证据 | 这一镜传达哪一事实，证据来自什么 |
| 屏幕文字／旁白 | 实际会出现或说出的完整文案；无文字／无旁白也明确 |
| 画面、光标与动作 | 元素、布局、进出、缩放、拖动、点击因果与重点 |
| 转场与连续锚点 | 哪个物体留在场上；位置、裁切、尺寸、颜色、速度如何交接 |
| 实现与素材 | 组件／图层、技术手法、asset id、需要的真实 UI／视频／3D |
| 声音与节奏 | 音乐事件、UI 声、旁白段、静音、SFX 峰值落点；不要求每镜有声 |
| 验收风险 | 小字、遮挡、快速形变、透明、照片对齐、视频寻帧等具体风险 |

常用叙事是“开场问题／结果→展示一次真实操作→关键能力与证明→品牌与 CTA”，不是每片都塞满所有功能。`outcome-story` 可以采用“任务→处理→时间推移→结果”；`tech-launch` 可以由一个数据流展示能力层次。

### 可读性先于快节奏

- 一镜一个主视觉焦点。字幕长度、字号和停留时间要在目标画幅与手机缩略尺寸下检查。
- 先让观众读完，文字再转成装饰或结构。旧标题离开占位后再让新标题进入；移动容器内文字有自己的 mask 和进出时间。
- 快切用于动作与简短词组，不靠逐帧暂停才能读懂产品名、核心卖点或 CTA。若信息装不下，减字、减镜或延长，不挤成小字。
- 竖屏、横屏、方形分别排版和验收；安全区围绕实际观众界面和用途设置，不假定横屏正中裁切就可交竖版。
- 结尾给品牌和行动足够停留。循环片同时设计首尾构图和速度连续性，不只让两个截图看起来像。

## 4. 把时间线做成可寻帧工程

目标是任意顺序求同一个时刻，都得到同一帧。HTML 管线通常提供异步 `window.seek(t)`，由绝对时间更新全部状态并等待素材就绪；其他技术用等价的 frame API。技术选型与实际 CLI 入口依本次环境，不能假定未创建的命令存在。

### 通用契约

1. 用单一主时间与明确的秒／帧换算。位置、透明度、蒙版、颜色、摄像机、光标、文字揭示、图表、计数器、视频与材质均由时间决定。
2. 不让 `setTimeout`、实时 CSS transition、上一帧状态、自由运行的物理或不固定的随机数决定导出。必要随机过程预计算或用固定种子与时间映射。
3. 对场景设定显式初值和终值；导出可先调用 t=12 再调用 t=2，不依赖从头播放才能正确。
4. 字体、图片 decode、视频 seek、贴图与异步资源完成后才截图。seek 返回不代表浏览器已完成所有异步绘制，需有明确 ready 条件。
5. 把文案、颜色、资产、镜头时间、关键位置和声音 cue 放到集中配置或清楚的组件中，使单点修改不需要重写整片。
6. 定义准确的 duration、fps 与总帧数。若 duration×fps 是整数，导出 `n=0…N-1` 的 N 帧；循环 t=T 用于连续性检查，不额外输出一张重复尾帧制造停顿。

### 技术注意点

- **native-html**：统一 draw／render／seek；Canvas 每次重置必要状态，辅助函数保存并恢复 transform、alpha、clip 和 composite。DOM 与 SVG 动画同样由 seek 显式求值。
- **GSAP**：使用暂停的主时间线并由导出器指定时间。避免仅在回调触发时换图或创建状态；确认跳转、倒退和重复求值一致。重建初始条件的方式应可复现。
- **Remotion**：以 frame／fps 为依据，使用可复现插值；管理异步素材与字体的等待。不混入自由运行的 CSS/定时器。参数化构图与不同画幅时，分别验证实际渲染输出。
- **Three.js**：按时间求相机、物体、材质和 shader uniform；预处理模型、贴图与 shader。检查透明排序、裁切、灯光、颜色空间与 GPU 限制。无必要不把二维卡片变成复杂三维场景。
- **Blender**：保存相机、灯光、材质、时间线和渲染设置；动画和模拟支持指定帧、必要时完成缓存；先验证少量关键帧和所需效果，再耗时全渲。
- **hybrid**：所有子片段回到同一分辨率、fps、时间起点与音频主时钟。记录原素材入／出点和速度映射，保留能重新合成的源文件。

### 弹簧与连续形变

闭式弹簧由“初始值 + 每次目标变化的阶跃响应之和”求出。每个变化在其开始时间前贡献为零，变化幅度是新旧目标之差；不能按当前帧把上帧速度继续积分。宽、高、半径、颜色与位置各有受控曲线，不必所有属性同时结束。

字形、图标或不兼容路径之间不要盲目插值任意控制点。用共同轮廓、蒙版、遮挡、视觉匹配或明确设计的中间形状衔接。打字进度由时间算字符数；光标闪烁也由绝对时间求值。

## 5. 声音与画面共用时间表

声音模式在 brief 内确定：可以无声、只用 UI 音效、音乐、旁白或组合。不要因参考片有音乐而强制加音乐，也不要为“气氛”盖住语音。

### 采用音乐时

- 读取真实音轨，分析 tempo、重拍、每小节能量、drop 与 breakdown，人工校准 kick 等关键事件。120 BPM 时每拍约 0.5 秒、四拍一小节约 2 秒，只是计算示例，不是所有影片的规定。
- 确定音轨起点再排镜头，区分音乐文件 0 秒和成片 0 秒。主要切点与视觉变换落在有理由的音乐事件，UI 小动作可落在细分拍上。
- 画面节奏不必被音乐绑架。文字读不完时调整文案、音轨区间、动作密度或片长，不把“每拍都有事”解释为每拍都换标题。
- 原创配乐也需实际生成、混音并听检；仅写“配乐已完成”或留一个空音轨不算交付。

### 音效按峰值定位

若声音文件的关键瞬态峰值在文件内偏移 `p` 秒，而动作发生在 `e` 秒，声音开始时间应为 `e−p`；裁切和淡入后重新确认峰值。不要把文件起点对齐按钮接触，却让真正的 click 晚半拍。

Sprites 方向可用合成的短 click／pop／确认音，强调轻、短、与动作有因果；Apple 和混合素材原例偏向下载的自然 SFX，该偏好只属于该参考路线，可以按用户选择改为合成或无声。

旁白使用真实合成结果定时，检查中文读音、产品名、单位和停顿。语音存在时，让音乐与效果退让；不通过削掉语音峰值换响度。响度目标由用途决定；参考原文常见约 −14 LUFS，但不是所有平台统一硬要求。测 integrated loudness、true peak 和是否削波，同时主观听检开头、衔接与结尾。

## 6. 所选风格的关键实施点

以下为可执行要点，完整镜头与措辞仍以对应原文按需读取。

### spotify-premium：主视觉连续与稳定舞台

来源：[brainextends-606193](original-prompts/brainextends-606193.md)。

- 将外部氛围背景、内部圆角舞台、hero、UI、前景文字、持久状态条分层。所有放大、卡片越界与镜头移动被舞台正确裁切，不能露出方角或把阴影裁得不一致。
- hero 作为一个有稳定身份的资产穿过“缩略图→搜索结果→详情→品牌色小卡→放大→多卡→Logo 收拢”。每次交接记录图像裁切、屏幕中心、尺寸与方向。相邻容器接力时，在交接帧匹配其可见边界，而非各自从默认位置淡入。
- 同一组卡片的移动有共同目的地、透视和层级，避免随机漂浮。大幅缩放时适度运动模糊；静止文字与封面保持清晰。
- 中段窄播放器／状态条作为稳定锚点：位置与尺度独立于主卡片镜头，不跟相机意外跳动；缩略图与 hero 一致，进度随时间，信息始终视觉次要。用户产品没有对应功能时改为合适状态条或移除，不制造播放器。
- 标题遮罩揭示、相机推进和内容变形协调开始／结束，旧文字完全退开后才进入新的占位；禁止无理由全屏交叉溶解掩盖接续问题。
- 收尾卡片收拢与 Logo 出现共享同一中心；图标移动到字标旁时始终留有间隔，检查快速经过时也不穿字。实际 hold 至结束。
- 建立异步 seek，检查 fast heading、搜索→封面、舞台变色、放大、聚拢和末尾字标的帧前后；这些比仅抽几个漂亮截图更容易暴露错误。

### minimal-ui 与 shape-morph：连续形状和真实操作

来源：[annacher-433425](original-prompts/annacher-433425.md)、[0xnicc0-516612](original-prompts/0xnicc0-516612.md)；问题／手势接续补充 [twoclipping-762046](original-prompts/twoclipping-762046.md)。

- 建立状态表：时间、形状边界、圆角、颜色、内容、光标动作、镜头。中间状态可共用一个主圆角矩形／Canvas 形状，内容单独分层，不靠每次创建新卡片伪装一镜。
- 内容在容器开始变形后进入，下一次变形前退出；每组文字有自己的 mask。相邻文字短交接也不能叠成两行幽灵字。
- 光标点击发生在真实按钮处；拖动按住期间值跟手，松手再按释放条件回弹。光标尺度随镜头统一，避免相机缩放但指针大小不变。
- 滑块、toggle 和 tab 的前后边缘可用不同响应形成拉伸，保持可读的控件语义；预算超拉等夸张动作须服务表达，不能被误读为真实产品支持越界值。
- 被镜头缩放的元素慎用 `will-change`，先对实际浏览器检查栅格化和清晰度；不能把原例性能设置无检查推广到所有工程。
- 采用 Sprites 声音路线时不加背景音乐；根据时间表合成 UI 音效，并以测得的瞬态峰值落到事件／拍点。
- 纯函数 typing、spring、图表与声音共用节奏表。循环检查光标起止位置与速度、shape 状态、输入文本和镜头；只匹配最后一张截图不足以消除顿挫。

### tech-launch：让转场解释功能

来源：[howdevelop-733090](original-prompts/howdevelop-733090.md)。

- 从一个问题或信号引出核心接口，节点接入解释可替换服务商，流在文字／波形／图片／视频之间连续转换解释模式，分支与独立进度解释并行任务。
- 以暂停→重连→从同处继续表现可靠性；用明确的检查动作表现类型或验证，不仅在画面上写“可靠”。每个特效都对应一项已确认能力。
- 真实术语控制在读得懂的短片段，代码有语义且字号足够；少量可编辑文字和矢量强于密集假终端。发布阶段和计划功能按当前资料核实，原例的数字与 release candidate 状态不能继承。
- 主内容按目标安全区排版；横屏内照顾竖屏安全区不等于竖版已完成，另版仍要布局验证。若有制作方署名，只有用户确实要求且事实正确才添加，不能套用原文 Studio1。
- 音效由克制脉冲到动能累积与收束；静音时故事仍完整。短片结尾也要能读完产品名和主张。

### real-ui：把真实界面拆成能说明产品的组件

来源：[ho-ba-761062](original-prompts/ho-ba-761062.md)；官网研究参考 [techtactician-144474](original-prompts/techtactician-144474.md) 与 [moritzkremb-466494](original-prompts/moritzkremb-466494.md)。

- 先捕获原 UI 并确定操作因果，再区分需要原样截图的内容与可以矢量重建的面板、图标和文字。按“动作→反馈→结果”编排。
- 让按钮、输入内容、结果卡片和图表分层，控制视线与镜头。只放大当前重要区域，背景保持低对比；不要整张截图反复推拉而无信息递进。
- 重建后对照原图检查功能名、布局关系、品牌、单位、真实交互结果。为画幅重排可以简化，但对外显示应忠于实际功能；演示数据在需要时说明。
- 缺少真实截图时不能声称已使用真实 UI。可用已确认事实搭演示组件，并在 brief／交付中明确；若用户严格要求真实界面，完成其他部分同时列出缺少的最小素材。
- 把原例的“做得像简历 showreel”转成质量目标，叙事仍由本次用户的产品与受众决定。

### social-launch：首秒钩子与产品证明

来源：[jhylee95-452427](original-prompts/jhylee95-452427.md)。

- 第一秒给明确问题、结果或反差，让用户立即知道与自己有关；不用只转一个品牌 Logo 消耗开头。
- 将产品证明与其他能力分成独立节拍；每个“好用”说法附一次能看懂的操作、结果或证据。AI 只有确实是产品能力时才出现，不默认每个 SaaS 都有 AI。
- 根据平台用少而可读的词；快速剪辑以视觉动作承接，品牌字、字体、颜色和真实 UI 仍一致。音乐存在时重定时到真实拍点；无音乐时采用清晰的视觉 cue。
- 检查静音首遍观看：观众能否复述产品做什么、为何有用、下一步是什么。不能用“病毒传播”替代可验证制作目标。

## apple-continuous 照片玻璃与 iris

来源：[twoclipping-496100](original-prompts/twoclipping-496100.md)。此节只在需要该复杂路线时读取。

### 资产和连续结构

- 原例依赖多张高质量照片、同场景白天／黄金时刻对齐照片、带植物影子运动的墙面视频、品牌字标和有 drop／breakdown 的音轨。按本次镜头选必要输入，缺素材时缩减或改路线；不要求每个用户都填满原例问卷。
- 先画物体的身份链，如字标→句点→pill→iris→照片→网格→玻璃工具→设备／页面→状态→墙面→字标。镜头不靠硬切或交叉淡化遮掉逻辑。参考原例“2D only”是该实现取舍，用户没指定时仍可选择其他适合技术。
- 光标点击、拖动、长按与镜头运动对应。日夜／光照变化使用对齐图片并保持主体位置，避免两张无关照片溶解成“真实重新打光”。

### 玻璃与 goo

- Chromium 中 `backdrop-filter: url(...)` 的位移表现存在兼容风险。可为每块玻璃复制其背后场景，保持相机与裁切一致，再对副本做位移、着色、边缘高光，避免只给白色半透明矩形冒充折射。
- 参考方案用圆角矩形距离场生成 SVG `feImage` 位移图，三个略有差别尺度的 `feDisplacementMap` 做克制的色边，再叠 rim light。玻璃字形可由每个 glyph 的 Canvas 距离场产生位移、mask 和高光。只在画面确实需要时实现；简单路线可减小折射强度，不必复杂化。
- goo 的模糊＋alpha threshold 放在独立离屏层，之后将清晰源图合回，保持玻璃内内容清晰。检查两个物体分离的临界帧，避免阈值导致闪断。

### Iris、字标和遮挡

- 六叶 iris 由六边形光圈展开；每片包含两个顶点、两侧延长边及连接它们的**短圆弧**。误用长弧会覆盖错误半屏。先单独验证开／闭极值和中间态，再接影片。
- 关闭 iris 时可按可见**面积**而非半径线性缓动，减少开头可见面积突变。全屏 flood 要越过四角，并给受控过渡时间；原例约 0.3 秒可作起点，最终按画幅与速度检查。
- 字标向句点挤压时，各字母朝同一点使用同一比例移动，字宽同步收缩；可用字体 `wdth` 轴或显式缩放，避免字母先分散再突然跳入点。
- 被变形的形状内文字需自己的裁切；`visibility: hidden` 的父层若有 `visible` 子层会漏出，可让子层继承。镜头缩放、边框生长与 mask 的边缘要按同一坐标系求值。

### 照片视频与声音

- 为准确寻帧，可将视频重编码为全帧内编码（如 ffmpeg 的 `-g 1`），预加载为 blob URL，seek 后等待 `seeked`／帧就绪再画。简单静态文件服务未必支持 Range，不能依赖其任意位置的视频读取正常。
- 音轨若存在，推进落在 drop，墙面段可安排 breakdown，字标回归落在拍子回归。SFX 以实测峰值对齐；用户选择无声或合成音时不继承原例“必须下载”的偏好。
- 关键帧至少覆盖 open、glass、stage、wall，以及形变前后；再逐帧查单帧跳动。帧差比邻帧高约 3 倍可作为候选报警，不能自动判每个音乐切点都是错误。

## footage-hybrid 真实素材与音轨对齐

来源：[twoclipping-000267](original-prompts/twoclipping-000267.md)。

- 真实素材墙与赢家筛选必须来自已获得的片段，选取内容能一眼理解的部分。关键输出用真实界面或明确标注的演示结果；收益数字、赢家指标不能凭视觉需要编造。
- 建立统一时间映射。浏览器逐帧导出可先将选定视频转为已知 fps 的图像序列，在 seek 时按源时间取索引，并等待 image decode；或用可靠的帧内编码＋视频 seek。序列为 30fps 而成片 60fps 时，明确采用重复、重采样或插值策略，不声称源素材获得了原生 60fps 细节。
- 视频转盘与 floor reflection 可以 CSS 3D 或 Three.js 实现。CSS `preserve-3d` 元素上设置 opacity／filter 可能使层级变平并出现两面同时可见，应在外层 wrapper 淡入淡出，独立控制反射。
- match cut 测量实际元素在镜头与布局下的屏幕边界，再映射下一镜；不要靠硬编码猜位置。真实 hero 从视频墙到手机时保留同一画面与入点。
- 音乐先定位实际强拍、drop 和每小节能量，再安排切点与 UI 事件。SFX 的峰值而非文件起点落在事件上，音效在音乐下保持克制。
- 先检查约 20 个或能覆盖全部高风险动作的代表帧，再做短动态样片，确认真实镜头解码、陈列翻面、手机过渡与音画同步，然后全片导出。数量随影片复杂度调整。

## outcome-story 与其他循环细节

来源：[twoclipping-747965](original-prompts/twoclipping-747965.md)；连续问答与手势补充 [twoclipping-762046](original-prompts/twoclipping-762046.md)。

- 将夜晚任务、执行过程与清晨成果换成当前产品真实的用户旅程。原例的品牌、线索／邮件／会议数、收入和默认照片都是例子，不可作为当前产品“默认事实”。
- 用离屏 Canvas 绘制句点内的世界，以圆形 mask 打开，而不是把摄像机猛推入偏离中心的微小圆点；后者容易造成横向甩动与速度尖峰。
- Goo 分裂／合并可在离屏层计算；每镜共享一张状态表，重定时只改关键时刻。帮助函数设置 globalAlpha 后恢复调用者状态，避免卡片突然显隐。
- 数字计数由输出帧的中心时刻求值；运动模糊只对运动属性采子帧，避免一个输出帧里出现多个数字的糊影。文字与需要清晰的 UI 同理可采用分层合成。
- 手势携带镜头进入下一场景，避免无目的推进后立即拉回。画面需要给阅读留时间时可停稳，原例“最长一秒不许停”不是所有语言和产品的硬要求。

## 7. 分阶段渲染并检查实际结果

### 先关键帧，再转场小样

先建立能代表设计的关键帧：开头、主要 UI、主视觉、结果、品牌收尾。按节拍或语义段导出 contact sheet，标明时间；在目标屏幕尺寸或缩略预览检查文字、间距、层级和安全区。

然后补查风险帧：文字交替前中后、hero 交接、相机最快时刻、glass／iris 极值、视频换源、Logo 汇聚、画幅边缘、循环接点。对这些位置导出几秒动态小样，带上最终的相应声音，而不是仅靠静帧推断运动正确。

检查乱序 seek：至少选择前后跳转、重复同一时刻、靠近转场边界的时刻，与顺序渲染的对应帧比对。检查是为验证可重复性，不需要为可逆的文案改动堆积无关单元测试。

关键帧与小样默认由 agent 自检并继续。用户要求“先给我看预览”或明确要求确认某阶段时，交相应产物并尊重该范围；原文中的 `<start>` 不自动增加批准步骤。

### 子帧与运动模糊

根据速度选择必要的 temporal samples，参考片通常 3–5 或 4 个子帧，而非盲目提高。围绕输出帧时刻采样，按清楚的 shutter interval 平均；静止文字与需要逐帧清晰的内容可分层保留。时间边界使用显式 clamp 或循环映射，不读取不存在的素材帧。

如果使用 ffmpeg `tmix`，明确区分“采样序列 fps”“输出 fps”“每输出帧包含几次采样”，验证平均窗口与帧重组。不能把普通 60fps 文件简单平均相邻帧就宣称得到参考要求的同帧子采样。先以快速移动对象试渲短片确认拖影方向与时长，合格后全片。

## 8. 全片导出与验收

只有用户已请求成片且实际导出成功，才把最终视频作为完成结果。浏览器里能播放 HTML、工程能编译或有漂亮截图，不代表 MP4 已交付。

### 编码与媒体检查

- 在实际环境渲染准确数量的帧并编码视频，声音按统一时间线合成。需要广泛兼容时可选 H.264＋yuv420p MP4；其他编码／透明背景由用途决定。
- 用可用的媒体探测工具核对容器、编码、像素、方向、fps、帧数、时长、音频采样率和声道。核对输出确实是预期 fps，不把复制或插帧称为所有元素原生真 60fps。
- 完整解码检查错误；从实际 MP4 抽取代表帧，播放开头、中段、关键转场和结尾，音画同步听检。检查文件可打开，音轨存在与否符合 brief，而不是只验证源工程。
- 视需求验证响度、true peak、削波、语音清楚、片头尾异常静音或截断。无声需求应无意外音轨；循环视频的画面与声音接点均检查。

### 内容与视觉检查

- 产品名、卖点、事实、版本、数字、Logo、URL 和 CTA 正确，无样例品牌或占位字残留。
- 无截字、乱码、重叠、过小字号、越界、闪帧、丢图、未加载字体、错误遮挡或空白片段。
- 主视觉一致、播放器／固定状态条稳定、镜头衔接和运动方向有理由；真实 UI 与产品事实对应。
- 静音首看仍能理解核心价值；旁白、字幕、屏幕文案在语义和时间上对应。
- 多比例逐一检查，不将一个比例的通过结论推广到其他导出。准确报告真正完成的版本。

有缺陷就定位修改并重渲受影响部分，再重新编码与验证。若环境缺渲染器或资源导致无法成片，交已完成源工程／预览与准确限制，不把近似产物叫“最终视频”；继续尝试现有环境内合理替代，不自行转向付费服务。

## 9. 可编辑交付与定点修改

### 交付物

按任务约定交付：最终视频优先；再给可播放预览、完整可编辑源工程、使用到的本地素材或可重建来源、brief、中文分镜、声音 cue 与素材来源记录。源工程应保留文案、品牌、颜色、资源、镜头和声音的清楚修改入口。

说明实际用的技术、入口文件、依赖、已验证的启动／渲染方法与环境条件。只给确实运行过或明确标注尚未验证的方法，不能编造 CLI 命令、把绝对本机路径当可移植入口，或遗漏关键素材导致他人无法复现。付费／受限制资产按其许可记录取得方式，不擅自重新分发。

无需为每片强行生成相同目录树；沿用用户现有工程结构。新项目可按 source、assets、audio、preview、output 等职责组织，避免把数千渲染帧误当必需源文件交付。保留足够信息重新渲染，临时中间帧按当前项目需要处理。

最终简要报告：视频路径、实际时长／比例／fps、声音形式、源工程位置、主要验证结果，以及任何会影响使用的限制。平台名称是交付规格，不能据此自行上传发布或投放广告。

### 修改流程

用户可按时间或内容定位，例如“0:04–0:07 搜索改成拍照识别”“结尾停留多一秒”“整片不要 BGM”。先映射到镜号、组件、素材和音轨，再改相关配置。

- 文案改变后重检换行、阅读时间与遮罩；换图后重检裁切和跨镜 hero 连续。
- 时间改变后更新后续镜头、声音 cue、总帧数和循环接点；不能只把片尾静止补长却声称所有镜头已重定时。
- 换声音后重新分析拍点／峰值；静音版仍检查字幕和语义完整。
- 技术与风格不必随单点修改全部推翻。完成受影响小样检查后导出新版本，再验证最终媒体，明确指出更新文件。
