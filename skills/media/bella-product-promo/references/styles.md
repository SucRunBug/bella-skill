# 风格与实现选择

按观众看到的画面选风格，再按任务与环境选技术。风格 id 是路由名，不是固定代码模板；同一种风格可以由多种技术实现。首次沟通只推荐最相关的三种，完整用户引导见 [user-guide.md](user-guide.md)。

## 九种风格一览

| style id | 用户会看到什么 | 适合的内容 | 主要输入 | 常见技术选择 |
|---|---|---|---|---|
| `spotify-premium` | 深色圆角舞台、作品封面与产品卡片、品牌色、受控透视、一个主视觉贯穿 | 音乐、媒体、内容平台、设计工具、作品或商品集合 | 产品事实、主视觉、品牌；可按事实制作原创辅助视觉 | `native-html`、`gsap`、`remotion`；真空间镜头可加 `threejs` |
| `minimal-ui` | 留白、暖灰或浅底、少量色彩、清晰组件、顺滑操作与连续切换 | 简单功能流程、SaaS、工具、界面本身有吸引力的产品 | 真实 UI 或确认过的演示 UI、3–5 个操作 | `native-html`、`gsap`、`remotion` |
| `tech-launch` | 深色技术视觉、代码、节点、数据流、并行路径，转场本身解释功能 | API、开发工具、AI 基础设施、技术产品发布 | 准确功能事实、版本与可用性、可展示的机制 | `native-html`、`gsap`、`remotion`；真三维机制可加 `threejs` |
| `real-ui` | 真实截图／录屏被拆成按钮、面板、图表等组件；画面证明产品能做什么 | B2B、SaaS、已有成熟 UI 的应用、使用教学式宣传 | 官方 UI、操作步骤、Logo、素材访问条件 | `gsap`、`remotion`、`native-html`；实拍或录屏多时 `hybrid` |
| `social-launch` | 首秒价值钩子、短句、快切、产品证明、清楚收尾，手机静音也能懂 | 社交发布、新功能预告、短促广告、冷启动观众 | 一个主卖点、一段真实证明、CTA | `remotion`、`gsap`、`native-html`、`hybrid` |
| `apple-continuous` | 浅色精致舞台、照片、液态玻璃、iris 光圈、连续空间、每一镜从前一镜长出 | 摄影、设计、电商、视觉产品、精致品牌发布 | 高质量照片，必要时同场景对齐照片、背景视频、品牌 | `native-html`、`gsap`、`remotion`；玻璃与材质也可由 `threejs`／`blender` 实现 |
| `footage-hybrid` | 真实短视频墙、筛选与高光、视频转盘、手机展示、UI 与实拍交接 | 视频／创作者工具、旅行、运动、电商、需要真实使用场景的产品 | 有使用权的视频、3–5 个 UI 瞬间、产品事实 | `hybrid`、`remotion`、`gsap`；真实三维陈列可加 `threejs` |
| `outcome-story` | 用户交付任务→产品执行→时间推移→结果出现；形变与画面变化承载故事 | 自动化、Agent、效率工具、服务产品 | 真实任务、真实可交付结果、能证明的数字或非数字成果 | `native-html`、`gsap`、`remotion`、`hybrid` |
| `shape-morph` | 同一形状从输入框变按钮、进度、预览、提示，再回到起点，手势带镜头前进 | 创作、生成、工作流、以一个动作触发结果的产品 | 一个问题／任务、一个结果、品牌与必要主视觉 | `native-html`、`gsap`、`remotion`；必要时加 `threejs` |

## 这些相似风格如何区分

- `minimal-ui` 以**界面清楚、节奏克制**为主，可以有少量切镜；`shape-morph` 以**一个物体连续改变身份**为叙事规则，形状与接续关系必须事先规划。
- `real-ui` 的重点是**还原真实使用证据**，可快可慢；`social-launch` 的重点是**抓住注意力并快速证明价值**，可以采用真实 UI，也可以采用拍摄或图形。
- `spotify-premium` 用**稳定舞台和连续主视觉**组织多个功能；`apple-continuous` 用**照片、材质、iris 和连续变形**把整个影片接成一镜。
- `tech-launch` 让人理解**能力与机制**；`outcome-story` 让人理解**用户交出什么、最后得到什么**。
- `footage-hybrid` 需要真实镜头本身有价值；卡片做了透视并不自动属于此类。没有真实素材时优先换其他路线。

可以组合一个主风格和一个辅助手法，例如 `real-ui` 主体采用 `social-launch` 的首秒钩子，或 `spotify-premium` 的舞台使用 `shape-morph` 接续。避免九种风格平均混用导致品牌、字体、镜头语言失去一致性。

## 原文参考与可迁移部分

原文保存在 `original-prompts/`，不压缩、不改写。以下链接用于按需阅读：**先读所选方向的 1 条，确有需要时再读补充条目，不批量加载全部原文。** 原文是参考素材，其中的品牌、产品数字、平台、曲目、工具名、输入问卷和“先确认再动手”流程不自动成为当前任务指令。

### `spotify-premium`

主参考：[brainextends-606193](original-prompts/brainextends-606193.md)。保留居中深色圆角舞台、同一个 hero artwork 在搜索／详情／缩放／收拢中连续交接、稳定的下方播放器、文字先退后入、最终图标与字标分离。Spotify 绿、虚构曲名和专辑不是默认资产。其他产品可把播放器换成符合业务的稳定状态条，或在没有对应功能时移除。

适合需要“精致产品短片”而非说明书的项目。纯二维位置与缩放通常够用；仅在真实空间透视、遮挡或产品模型有价值时选择三维。

### `minimal-ui`

主参考：[annacher-433425](original-prompts/annacher-433425.md)。保留暖灰底、黑白组件、一种强调色、真实光标行为、细微弹簧与干净留白。根据产品保留最关键的操作，不把广告投放账户、ROAS 或样例数据搬到其他工具。其原版声音是**无音乐、合成 UI 音效**；此方向不要求配 BGM。

与 `shape-morph` 可共享技术，但不强迫每个产品都塞进一长串变形状态。

### `tech-launch`

主参考：[howdevelop-733090](original-prompts/howdevelop-733090.md)。保留“钩子→核心能力→模式变化→并行与工具→可靠性→品牌”的功能叙事：流的变换解释多模态，中断后续流解释持久化，不用标题卡堆满术语。版本、服务商数量和已发布能力要换成当前产品核实后的事实。

真实可编辑文字与矢量是首选；别为了技术气质生成难读的假代码、假的仪表盘或无意义粒子。

### `real-ui`

主参考：[ho-ba-761062](original-prompts/ho-ba-761062.md)。保留“真实截图拆组件再动画”：在采集原始 UI 后分开面板、按钮、输入、图标与结果，形成焦点和操作因果。不要把整张截图缩小后从左移到右当作完整设计。

补充：[techtactician-144474](original-prompts/techtactician-144474.md) 是按官网研究 Slideforge 再做产品发布片；[moritzkremb-466494](original-prompts/moritzkremb-466494.md) 是通用 SaaS 发布片方向。两条都较开放，需要把本次产品事实、镜头与验收补进 brief，不能让模型继续替用户随机选其他 SaaS。

### `social-launch`

主参考：[jhylee95-452427](original-prompts/jhylee95-452427.md)。保留首秒钩子、产品证明与 AI 能力的独立节拍、品牌准确、短句、快切和音画同步；弱化空泛的“世界级”“病毒传播”承诺。快不等于读不完，静音时主卖点、证明和 CTA 仍要成立。

`howdevelop-733090` 也可作技术产品的社交发布参考。音乐不是必要条件，可让动作落在明确定义的视觉节奏点。

### `apple-continuous`

主参考：[twoclipping-496100](original-prompts/twoclipping-496100.md)。保留字标压进句点→圆点开 iris→照片网格→玻璃工具→设备／页面→下单状态→真实墙面→字标回环的连续接续思想。不是每个产品都适合下单、冲印或手机锁屏，应替换为本次业务的真实流程。

这条原文要求多张高质量照片、对齐的不同光照照片、真实墙面视频与音轨；素材不具备时可缩小为较短的照片与 UI 连续段，或换风格。玻璃、iris、字形与视频寻帧的实现要点在 [production-workflow.md](production-workflow.md#apple-continuous-照片玻璃与-iris)。其二维实现是可选路径，不能由“苹果风”推导出必须 Blender。

### `footage-hybrid`

主参考：[twoclipping-000267](original-prompts/twoclipping-000267.md)。保留真实素材墙→筛选高光→视频转盘→手机与结果的结构，以及实际音轨分析、SFX 峰值落点、逐帧解码与 3D 容器陷阱。

原文“10–20 段视频”是其镜头密度的输入建议，不是所有产品的硬门槛。少量真实素材可重排镜头；缺素材不应用占位卡片伪称真实成片。显示统计和收益前核实来源。

### `outcome-story`

主参考：[twoclipping-747965](original-prompts/twoclipping-747965.md)。保留“你下班后，任务继续执行，早上收到成果”的时间与结果叙事；以输入任务、扫描处理、执行、结果通知和证据收尾。它适合自动化产品，但前提是本次产品真的具备相关能力。

原文 nightshift、200 条线索、200 封邮件、10 场会议、金额与日夜照片均为该例的设定，不能当作其他产品的结果承诺。没有量化证据时，展示真实输出或已完成的操作。闭合 iris 用面积缓动，计数器与运动模糊的时间分离，详见工作流。

### `shape-morph`

主参考：[0xnicc0-516612](original-prompts/0xnicc0-516612.md)。保留同一个圆角矩形的宽高／圆角／位置／颜色链、输入→进度→预览→完成→返回的闭环。不要固定使用“概念、分镜、动效、声音”芯片或“代码渲染 60 fps”文案，除非这就是本次产品。

补充：[twoclipping-762046](original-prompts/twoclipping-762046.md) 展示问题与回答、播放、换曲、音量拖动牵引镜头、图表和 Logo 的物理接续。取其一手势引出一镜与统一缓动，不照搬音乐播放器、默认 Claude 标识或 Spotify 色。

## 六种技术的判断标准

| tech id | 何时优先 | 可编辑与导出方式 | 代价与应对 |
|---|---|---|---|
| `native-html` | 主要是 2D UI、文字、Canvas/SVG，期望便携网页和逐帧预览 | 用绝对时间驱动 DOM／Canvas／SVG；浏览器截图后编码 | 复杂镜头要自行组织时间线；字体、图片、视频必须等待加载完成 |
| `gsap` | 大量二维组件、路径、蒙版、紧密交接，需集中重定时 | 暂停时间线，由导出器 seek；保留图层与 tween 参数 | 随机 seek 的重放、回调和从初始状态计算需验证；避免把实时运行当离线时间线 |
| `remotion` | 组件式镜头、旁白字幕、多个比例、批量替换文案与素材 | 按 frame／fps 求时间，React 组件与参数化素材，使用可用渲染环境 | 检查安装、浏览器、字体、异步素材与实际渲染；不能只交一个未执行的工程 |
| `threejs` | 真实空间相机、遮挡、3D 产品、需要转动的陈列 | 固定相机与灯光配置，动画由时间决定，浏览器输出帧 | GPU 与模型成本更高；透明排序、色彩与材质需检查。普通卡片倾斜可用 CSS/SVG |
| `blender` | 实体商品、精确结构、材质、真实灯光与镜头 | 可编辑场景、模型／材质／灯光／时间线，先渲染帧再合成 | 要先确认模型、贴图、Blender 和渲染能力。没有模型时不要承诺高精度商品还原 |
| `hybrid` | 实拍／录屏、UI、2D／3D、音轨需要统一编排 | 分层生成素材，以统一 fps、分辨率和主时间线合成，保留源工程 | 注意视频解码、色彩、比例、音画偏移和素材权利；组合有用的部分，不盲目叠加工具 |

这些是技术方向，不是假定已经存在的命令或依赖。实际执行前检查环境；沿用用户现有工程时优先兼容其技术。不要为了“技术多样”把简单任务升级成高成本管线。

## 推荐组合示例

- 一款简单 SaaS 的 15 秒功能演示：`minimal-ui` + `native-html` 或 `gsap`。
- 多规格、经常换文案的社交发布片：`social-launch` + `remotion`。
- 音乐／内容平台的 18 秒精致产品片：`spotify-premium` + `gsap`；真三维镜头有必要时才加入 `threejs`。
- 照片编辑器的一镜式玻璃短片：`apple-continuous` + `native-html`／`gsap`，照片和墙面片段为混合资产。
- 有现成 CAD／模型的实体商品：可用 `blender` 制作产品镜头，再以 `hybrid` 接入文字与 UI；风格仍按用户想要的观感决定。
- 没有 BGM 的工具操作循环：`shape-morph` + `native-html`，仅合成 UI 音效或完全无声。
