# 小红书Bot图文包

把主题变成能收藏、能接话的图文。参考“什么都别买贵了bot”“9.9r也可以爽买bot”的人群提问、低预算满足感和评论区共创，保留用户自己的品牌。

## 两阶段是默认流程

用户明确要求先确定视觉风格。新主题先进入**方案阶段**：配齐选题、文案和视觉规范，但不调用图片生成、图片编辑或付费生图工具，不生成封面样张。用户明确确认本次方案后才进入**制作阶段**。

“就按这个”“确认，用A方案”“IP换成这张，其余不变，然后生成”可授权相应方案与明确修改。沉默、旧主题曾确认、已有历史图片都不是新主题确认。“沿用上一套，直接生成”且旧方案可明确识别时，可视为本次授权。只授权封面或样张时，不扩成全套。

主题、配色、版式、IP实质变化时更新方案版本，不用旧确认替代新确认。修正错字、核价和已授权的局部修改，不重复索要整套确认。

## 输入与默认

只需主题；可选人群、预算、品类、发布日期、对标链接、IP、商品名单和视觉参考。用户要求优先。

- 默认面向年轻女生，再收窄为大学生、初入职场或独居等具体人群。
- 商品类默认9款，每页3款，1张封面＋3张3:4内页。非商品类用9条有依据的建议或经验线索，不强行推荐商品。
- 蓝白粉是默认**候选**风格，不是自动批准。账号标签默认“小钱过好日子bot”，可改。
- 猫咪身份见内置已确认封面；不打印“月薪喵”，不加已删除的“经验征集｜食物为示意图”。
- 节点依客户端当前日期、时区及用户发布日期核对，不固定11月或双十一。
- 默认只交本地文件，不发布笔记、不购买、不联系商家。

保存到当前工作区 `outputs/xhs-bot/<发布日期>-<主题>/`。续作先读该任务的方案与 `内容数据.json`，保留确认版本和已完成素材。

## 阶段一：完整方案，等待确认

1. 阅读 [文案与选题](references/editorial.md)，把主题写成“谁＋场景＋限制＋想得到什么答案”。联网核对真实相关的季节、促销、校园节点或热梗，保留来源与观察日期。不因给了一个主题就重做15篇账号研究；用户要求周排期或对标调研时才扩大样本。
2. 商品类按 [选品与证据](references/research.md) 查候选，筛9款，核对名称、口味/型号、购买单位、克重/数量、可见参考价、渠道、真实商品图。食品补保存要求；配料在用户要求或影响选择时查对应背标。资料不足先换候选或说明缺口，不编造试吃、销量或投稿。
3. 写1个推荐标题＋4个备选，默认20字以内，带适合主题的Bot口吻。另写封面提问。完成约250–450字正文、6–10个标签、首评、3页逐字稿、2–4句爆款逻辑。“爆款”指表达与潜力，不承诺流量。
4. 阅读 [视觉规范](references/visual-system.md) 和 [生图模板](references/image-prompts.md)。以文字、表格、现成参考文件提交具体方案，不生成新图。至少给出：
   - 推荐风格与读者阅读顺序。
   - **用途／色名与HEX／使用方式**的配色表。
   - 封面顶部、中部、底部结构、3:4画幅、安全边距和信息层级。
   - 字体、大小比例、换行与字数控制。
   - IP身份、位置、姿态、装饰规范。
   - 3张内页分组、每页3款的交错布局、名称/价格/理由/提醒位置。
   - 封面及各页完整文字、准备使用的参考图、尚未核实的关键资料。
5. 保存 `视觉与内容方案.md`、`发布文案.md`、`内容数据.json`，按 [交付结构](references/delivery-contract.md) 设置 `stage: proposal`、方案版本与待确认状态。必要时先制作选品表。

回复直接展示核心配色表和版式，链接完整稿，请用户确认本次配色、排版与IP，然后停止本轮。不要把提示词或历史参考图称为本次成品。

## 阶段二：用户确认后生成

记录用户实际确认的文字摘要和方案版本，设置 `approval.confirmed: true`；不能由模型自行批准。

1. 采用用户已选生图路线，遵从宿主当前图像技能、接口和费用授权。历史两例用内置 `image_gen`，沿用时不重新推销或切服务；工具不可用时如实说明并完成其他可做部分。
2. 先检查本地参考图，再生成封面。说明每张图是风格、IP还是商品参考；旧图的标题、日期、价格不进入新稿。
3. 目视检查封面后继续3张内页，不重复要求已批准的确认。先一页建立系列风格，再生成其余页。使用真实商品参考，不发明包装、品牌、净重或配料。
4. 每张图检查中文、品牌、口味、价格、克重、数量、页码、图文对应、裁切及手机可读性。错误做局部修正；缺图不能称整包完成。
5. 商品类按宿主电子表格技能创建带图片和来源链接的 `.xlsx`；无法创建时交CSV并说明。非商品类提供内容来源表即可。
6. 最终图片复制到任务工作区，保留方案、文案、`生图提示词.md`、`核价与来源.md`、选品表和内容数据。完成后用下列脚本检查与打包。

```bash
python3 <技能目录>/scripts/pack_delivery.py validate-plan <任务目录>/内容数据.json
python3 <技能目录>/scripts/pack_delivery.py validate <任务目录>/内容数据.json
python3 <技能目录>/scripts/pack_delivery.py package <任务目录>/内容数据.json --output <任务目录>/完整图文包.zip
```

脚本只检查文件、字段、价格约束和确认记录，不代替事实核对与目视检查。最终返回成品图、文案、来源表和压缩包链接，并简短说明影响选购的限制。
